## Supported composition at the reviewed version

The reviewed API supports tasks, static/runtime Jev requests, returning conditionals, static parallel lanes, bounded maps and bounded loops. Map/loop template callbacks build once; their runtime bodies operate on resolved item/state/context inputs. Returning conditionals are useful inside both.

At v0.5.3, nested maps, nested loops and loops inside maps are unsupported. A loop can contain one map level. Terminal outputs/branches do not belong in value-returning map/loop bodies or `if()` arms. The body returns an expression; a loop returns its state type. Read `docs/flows.md` for current numeric limits, failure behavior and budget accounting rather than copying stale limits into a new design.

Expression `all`/`any` evaluate every operand; they do not provide JavaScript short-circuit guards for missing values. Compute such predicates in a task or use supported explicit conditional paths. `get()` reads JSON object/array fields, not primitive properties. Structural IDs must be unique across the definition, including untaken paths; use static, non-sensitive labels rather than interpolating document text.

For larger fixed rubrics, explicit per-question gates can expose routing within one repeat item. Do not turn every arithmetic operation into a diagram node; group a coherent deterministic transformation in a named task. Conversely, hiding all requests and routing in one task defeats linked inspection. Let the source's meaningful decisions determine the graph.
