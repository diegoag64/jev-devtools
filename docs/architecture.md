# Architecture

Application code uses three JavaScript entry points: the SSR-safe React component (`jev-devtools`), a Node server adapter (`jev-devtools/server`), and the server-only flow API (`jev-devtools/flow`). Browser-safe trace types are exported from the React entry. Server modules and the TypeSafe SDK must never enter the browser bundle.

`createJevDevtools()` owns a bounded in-memory recorder. Its `createClient()` instruments the SDK's `systemOne` calls while preserving APIPromise behavior. AsyncLocalStorage links retries to the logical call. The adapter exposes configuration, SSE snapshots, and scoped clearing; the React drawer handles subscriptions and displays diagrams. There is no network interception or hidden-model reasoning capture.

`apps/playground` uses only package exports. Its custom fetch fixtures pass through the real SDK. It owns cookbook guides, fixed sample inputs, and the workbench controls. Preview captures and sample runs share the same recipe setup; previews use a private recorder while runs stream into the visible inspector. These are not inspector policies or package dependencies.

`getJevDevtools(key, createOptions)` shares an adapter in a versioned global registry within one Node realm. Its first configuration remains active across module reloads; disposal removes the key. It does not aggregate across processes.

`examples/nextjs-app` uses the packed library through App Router routes, Server Actions, and Server Components. `verify:nextjs` checks real framework routing, shared traces, reload retention, SSE, and disabled production endpoints.

`examples/react-vite` installs a packed tarball. The verification script copies it outside the workspace so it cannot accidentally resolve internal source or hoisted dependencies. CI checks React 18 and 19 and Node 22.12 and 24. The regular build intentionally creates a local-only notice; a separate check compiles the full development UI.

## Request capture views

`capture()` bounds and redacts request and response content. `projectTraceCapture()` in `src/capture-view.ts` validates that JSON before the recorder assigns typed views. It retains incompatible content in `Trace.capture` with warnings and supplies an empty request view or omits the result. It never reads original application values to reconstruct a view. Browser consumers validate individual captured fields and retain usable siblings, with unavailable paths held in a browser-only WeakMap. The display uses only captured JSON, including legacy captures; valid records preserve identity. Replay export still rejects responses with incompatible structured shapes. Transport validation owns the structural envelope separately. See [transformed captures](stream-protocol.md#transformed-request-and-response-captures).

## Connected flows

`defineJevFlow()` builds a bounded graph once; each `run()` executes an independent instance in the Node process. Version 0.4.0 supports Jev requests, server function tasks, runtime request factories, parallel lanes, terminal branches, value-returning conditionals, collections, and stateful loops. A shared inspector links each Jev step to its full request capture. Task data, collection items, and iteration state use bounded/redacted snapshots; runtime values remain independent of capture limits.

Definitions and runs are separate version-1 records streamed over `/flows/events`. The 0.4.0 drawer understands task, collection, merge, and loop records; keep the server and drawer on the same build. Definitions are limited to 256 nodes including templates and 16 nested blocks, while a run shares a 1,024-expanded-step budget. Execution is in-process with cooperative cancellation, without durable state, resume, or automatic task retries. See the [flow guide](flows.md) for scope and nesting constraints.

## Flow capture boundaries

Execution values and inspector captures have different owners. The [capture path/context table](integration.md#capture-paths-and-context) defines the callback boundary. Custom callbacks receive bounded detached views and a frozen capture kind. Private omission guards prevent policies from confusing cutoffs with ordinary missing data; warnings survive root replacements. Task/child caches include the callback path so reused data cannot inherit another path's policy. When changing capture limits, redaction, or warning metadata, trace every boundary below, including nested map/loop runs. A loss before the recorder cannot be recovered by adding recorder warnings alone. The warning and [fidelity contract](stream-protocol.md#capture-fidelity-and-analysis-consumers) is in the stream protocol. Fidelity combines conservatively across rule projection, observer snapshots, recorder traversal, and browser projections. Missing provenance stays unknown; custom callbacks cannot certify exactness. Detachment omissions downgrade fidelity even when a callback replaces the root.

## Limits

One Node process/adapter instance, same-origin browser endpoint, memory-only traces, and explicit opt-in. Non-loopback access requires application authorization. Distributed workers, serverless aggregation, edge runtimes, persistent traces, and automatic discovery of arbitrary SDK clients are outside this prototype. Live inference and browser visual QA must be reported separately from sample and SSR checks.

## Isolated UI and diagram camera

The client drawer portals into an open ShadowRoot on a `jev-devtools-root` host. Its root resets inherited typography and layout, while shadow encapsulation keeps host selectors out of internal cards, headers, and controls. `copy-styles.mjs` embeds `inspector.css` in the component’s JavaScript. The component loads that embedded stylesheet automatically; consumers do not need a CSS import. The host and listeners are removed on unmount, including React Strict Mode cleanup.

The diagram camera uses pointer capture and animation-frame transform updates rather than a scrollable scaled container. Wheel zoom preserves the diagram coordinate beneath the pointer, two-finger pinch also follows its moving midpoint, and Fit considers both viewport dimensions. ResizeObserver refits a fitted view or keeps a manually positioned view centered when the drawer changes size. Camera geometry tests cover full-content fitting, anchored/clamped zoom, and moving pinch.
